# Лабораторная работа №2
## Линейные структуры данных: Музыкальный плейлист

### Описание
В этой работе реализована программа на Python для управления музыкальным плейлистом. Каждый трек представляет собой объект класса `Track` со следующими свойствами:
* Название (title)
* Длительность в секундах (duration)
* Жанр (genre)
* Рейтинг (rating)

---

### Что реализовано в коде

#### Обязательная часть:
1. `add_track` — добавление новой песни в конец списка.
2. `remove_track` — удаление песни по её индексу с проверкой корректности номера.
3. `shuffle_playlist` — случайное перемешивание всех треков.
4. `set_repeat` — переключение режимов повтора (none, one, all).

#### Вариативная часть:
* **Задание 2:** `load_from_base64_file` — чтение текстового файла, декодирование строк из Base64 и автоматическое восстановление треков в массив.
* **Задание 5:** `filter_by_genre` — поиск и вывод на экран всех треков определенного жанра (регистр букв не важен).

---

### Обоснование выбора структуры данных

В качестве структуры данных был выбран **динамический массив** (встроенный список `list` в Python).

**Почему массив лучше связного списка (LinkedList) для этой задачи:**
1. **Быстрый доступ по индексу ($O(1)$):** В плейлисте постоянно нужен доступ к конкретному элементу (удалить трек №3, включить случайный трек, вывести трек по номеру). Массив делает это мгновенно. В LinkedList пришлось бы каждый раз перебирать элементы с самого начала, что заняло бы $O(n)$ времени.
2. **Удобное перемешивание:** Стандартная функция `random.shuffle()` эффективно работает именно с индексируемыми структурами данных, как массив.
3. **Память:** Массив хранит только ссылки на треки, а LinkedList требовал бы дополнительную память под указатели на следующие узлы.
4. **Перебор элементов:** Для фильтрации по жанру нам нужно пройтись по всему списку. Из-за кэш-локальности динамический массив делает последовательный обход быстрее.

### Обработка крайних случаев
В программе учтены возможные ошибки, чтобы код не падал во время работы:
* При удалении трека проверяется, не пустой ли список и не выходит ли индекс за его пределы.
* При перемешивании проверяется количество треков (если треков меньше двух, программа выдает предупреждение).
* При чтении файла Base64 добавлена защита от отсутствия файла на диске (`FileNotFoundError`) и от пустых строк.
